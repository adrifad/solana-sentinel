# Solana Sentinel Implementation Status

## Initial gap analysis

The provided checkout was a documentation blueprint, not an application. It contained only `AGENTS.md`, `README.md`, `SOLANA_SENTINEL_FULL_SPEC.md`, and a root-level `default.yaml`; the individually referenced `docs/` pages, canonical `config/default.yaml`, workspace, code, tests, migrations, and container files were absent. The compiled specification is retained unchanged and used as the implementation source.

## Delivered in this slice

- Strict TypeScript pnpm workspace and Zod/YAML validated mainnet `DRY_RUN` configuration.
- SQLite WAL migrations through version 8, durable normalized PumpPortal events, bounded sanitized payloads, idempotency, separate provider-reported and verified chain slots, reported creator/trader roles, and provenance timestamps.
- One PumpPortal WebSocket client with message and pending-handler bounds, heartbeat, reconnect/backoff, resubscription, and callback draining during shutdown. Handler concurrency and pending queue capacity are validated runtime configuration (`event_processing_concurrency`, `max_pending_events`). Incoming events are persisted before asynchronous enrichment/processing; overflow closes the stream and is recorded as an unrecovered gap. Socket health and queued-event completion are now bound to the receiving socket session, so callbacks from a disconnected or superseded session cannot report `HEALTHY` or close an unreconciled gap. `waitForIdle()` exposes a deterministic event-drain boundary for shutdown and lifecycle validation.
- Helius JSON-RPC reader with response validation, timeout, retries, circuit breaker, per-second pacing, persistent UTC-day request budget, and safe error codes.
- A durable SQLite enrichment queue consumes only monitoring-eligible events, claims work with bounded concurrency, retries transient failures, and recovers interrupted jobs after restart. Migration events use separate durable recovery and analysis queues; signature, mint association, transaction success, and provider-slot agreement are checked before an atomic chain-slot and migration-slot update. Shutdown waits for claimed requests to settle before closing SQLite.
- Provider health stores socket state, last event/message time, last processed time, processing lag, queue depth, reconnect count, and provider error code separately. A shutdown drain cannot change `STOPPED` back to `HEALTHY`.
- Mint-account status and blockchain timestamp status are independent. A timestamp lookup failure does not erase a validated mint-account result, and successful timestamp results are retained across retries.
- Reused idempotency keys with contradictory slot or token metadata are recorded as provider conflicts. Signatures are preferred as event keys, then usable slots, then a deterministic payload digest; missing metadata does not silently merge unrelated events. Stream completeness reports unreconciled gaps and never labels observed stream data as complete history.
- Read-only worker commands and API health/readiness/token routes, with readiness based on PumpPortal heartbeat freshness; no dashboard, signing, sending, wallet key, paper fills, or live arming.
- Fixture tests for config fail-closed cases, malformed/duplicate/out-of-order events, monitoring caps, Helius malformed responses and secret redaction.
- Creator intelligence foundation: Pump CreateEvent decoding against the current public IDL layout; distinct claimed creator, launch initiator (`user`), and transaction fee payer evidence; historical finalized wallet signature pagination and transaction ingestion; cached, as-of-slot creator launch history; direct funding observations and repeated co-signer evidence with confidence. Direct exchange funding evidence is retained as a weak edge and is excluded from suspected-cluster membership.
- Token security foundation: SPL Token mint-state decoding, Token-2022 TLV parsing with unknown/malformed extensions failing closed, authority checks, metadata-only test-token heuristic, supply/holder snapshot comparisons, and sampled creator/cluster concentration.
- Explainable DRY_RUN analysis: token creations and terminal migration recovery outcomes have durable analysis jobs, security reports, risk decisions, reason codes, evidence references, config hash, timestamp, and latency. Jobs recover after restart and incomplete history/security work is refreshed with bounded backoff. Migration-first discovery never infers creator identity from a migration signer; missing creation evidence remains unknown and is quarantined. Over-budget tokens receive a missing-data report without Helius calls. No buy intent is generated while launch behavior, validated holder sample coverage, or exit quote requirements are incomplete.
- Sprint 2.5 additions: parsed historical pre/post token balances produce evidence-backed queried-wallet outflow indicators (not a proven sell/rug); normalized launch behavior snapshots classify only complete observation windows, flag possible same-wallet wash patterns, and filter data after the decision timestamp; quote/snapshot/exit-validation domain contracts and migration 006 persist observations, behavior snapshots, quote results, wallet outflows, and Jupiter request budgets.
- Quote support now includes bounded Helius state loaders for supported Pump bonding curves and canonical WSOL PumpSwap pools. `PumpCurveStateLoader` validates mint/curve/global/fee/ATA owners and coherent state before calling the pinned `@pump-fun/pump-sdk@4.1.0`; `PumpSwapStateLoader` loads pool/global/fee/mint/vault state, validates pool/vault relationships and slots, and calls the pinned `@pump-fun/pump-swap-sdk@2.1.0`. Unsupported quote mints, custom PumpSwap pools, stale or incoherent snapshots, migrated curve state, and unavailable exit liquidity fail closed. The read-only quote engines return exact-input outputs, fee decomposition, price impact, snapshot provenance, and exit-liquidity checks. Opt-in Jupiter V2 `/order` remains read-only and cannot replace missing required on-chain snapshot evidence.
- Holder evidence now distinguishes sample count, validated decoded sample, and sample supply coverage. `holderSampleComplete` remains false. The configurable 90% supply-coverage threshold is heuristic and is not an exhaustive distribution or a validated security guarantee.
- `analyzeLaunchBehavior` consumes persisted, time- and slot-bounded trade observations. The worker now persists a behavior snapshot when observations exist and attaches it to the DRY_RUN decision evidence. Since a persisted trade list does not prove uninterrupted stream coverage, worker-generated snapshots remain incomplete with `TRADE_STREAM_COMPLETENESS_UNVERIFIED`; the risk engine quarantines rather than treating sampled observations as a completed window. PumpPortal metered token-trade subscriptions remain disabled (`enable_token_trades: false`): the live provider denied activation because its linked wallet did not meet the documented 0.02 SOL minimum, and no trade payload was received. Subscription lifecycle, event budgets, reconnect coverage, and trade normalization remain unimplemented.
- Read-only detail routes expose token role evidence/security/decisions and creator reputation/launches/wallet links.
- PumpPortal frame dispatch separates token events, provider errors, known subscription acknowledgements, unsupported frames, and malformed frames. Bounded sanitized diagnostics and reason codes are persisted; token detail exposes analysis/recovery status and health exposes recent provider diagnostics.
- PAPER foundation (not active application mode): the signer-free `@sentinel/paper` package provides exact SOL-to-lamport conversion, a quote-at-simulated-arrival provider contract, current Pump curve/PumpSwap state-backed read-only quotes, conservative bigint slippage, idempotent order recovery, atomic SQLite fill/position/journal updates, per-asset double-entry balancing, immutable ledger triggers, realized/unrealized portfolio PnL, unpriceable exposure, daily realized-loss/drawdown/open-position/exposure gates, and time/stop/take-profit exit evaluation. Migration 007 adds persistent account, order, fill, journal, position, PnL, and equity-mark records. The package is not imported by worker/API; `APP_MODE=PAPER` remains rejected and DRY_RUN cannot call paper settlement.
- PAPER SELL gates apply max trade size and the entry pause only to BUYs. SELLs may reduce held positions above the BUY size cap or after drawdown, while atomic settlement still validates holdings, quote freshness, liquidity, fees, slippage, and SOL accounting. The existing `risk.emergency_pause` setting maps to `pauseNewEntries`; emergency liquidation is not implemented.

## Provider contract limits

The official PumpPortal streaming reference verifies the WebSocket URL, `subscribeNewToken`, `subscribeMigration`, and one-connection guidance, but does not publish event payload schemas or define `traderPublicKey` versus `creator`. A sanitized third-party PumpPortal create-event capture is checked in at `tests/fixtures/pumpportal-created.mainnet.capture.json`, with provenance in its evidence sidecar. Its signature was independently read from finalized mainnet RPC: the transaction signer and Pump create instruction's `user` account match `traderPublicKey`. This supports interpreting that field as the launch transaction initiator for this observed legacy create event; it does not prove that it is the token's canonical creator in all launch versions. The current Pump public IDL's `CreateEvent` separates `user` and `creator`; runtime evidence decoding records them separately, and the transaction's first required signer is stored as fee payer. The capture is third-party, not an official provider contract fixture, and was not collected in a live PumpPortal session. The current IDL parser is pinned to the documented event discriminator and field order; historical IDL compatibility is not established.

No sanitized PumpPortal migration-event capture was available. The configured trade subscription was denied at the linked-wallet funding gate, so no trade payload was received. Migration payload shape and role semantics therefore remain unvalidated. Existing `.synthetic.json` launch/migration fixtures are explicitly synthetic contract cases, not provider evidence. Creator Intelligence is implemented for create events that can be verified from finalized transactions; provider migration semantics and complete launch-version coverage remain a blocker to treating discovery as comprehensive.

PumpPortal does not document replay/cursor support on the public streaming page. A disconnect therefore creates a persisted gap record, and reconnection marks it `UNRECOVERED`. No complete-history claim is made. Helius can query known addresses/signatures, but a full missed-launch scan requires a verified program/event decoder and paging strategy that this foundation does not yet implement.

Helius uses the documented mainnet RPC endpoint and standard Solana `getHealth`, `getGenesisHash`, `getAccountInfo`, `getBlockTime`, `getSignaturesForAddress`, `getTransaction`, `getTokenSupply`, `getTokenLargestAccounts`, and `getMultipleAccounts` methods. Historical calls use finalized transaction data and are bounded by page size, analysis concurrency, a per-request rate limit, and a persisted UTC-day request budget. `getBlockTime` is an estimated ledger timestamp, separate from local receipt time. Mint and holder snapshots use confirmed RPC state and are checked for slot skew, freshness, and amount consistency. Without Helius credentials, chain history, mint state, and holder state remain unknown rather than inferred. The Helius credit cost is not separately calculated; the enforced limit is RPC request count, and plan-dependent provider costs were not validated.

The baseline retains later-phase paper/risk settings as validated templates. Jupiter is an opt-in quote-only adapter with persistent rate budget; DEX Screener, social intelligence, and metered PumpPortal token-trade streaming remain disabled. No provider response is substituted with fabricated market data.

SQLite currently uses Node's built-in `node:sqlite` API. Node's official docs classify this API as Release Candidate in supported Node 24/26, so this reduces native dependency/setup complexity but remains a pre-stable runtime API risk for production. Pin Node and the SQLite API behavior, or replace the adapter with a stable SQLite binding before treating the service as production-ready.

## Safe startup

1. Use Node.js 24 or 26 and pnpm 11.
2. Copy `.env.example` to `.env`, set `PUMPPORTAL_API_KEY` and optionally `HELIUS_API_KEY`; keep the PumpPortal key private because it can be associated with a funded wallet.
3. Run `pnpm install --frozen-lockfile`, `pnpm db:migrate`, `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, and `pnpm docs:check`.
4. Start read-only discovery with `pnpm dev:worker`; the process refuses to start if the feed key is absent. In a second terminal, `pnpm dev:api` binds to `127.0.0.1:8787` by default.
5. Use `pnpm tokens` and `pnpm health` for local inspection. Only GET routes are implemented.

`APP_MODE` may only be `DRY_RUN` in this build. No credentials are needed for the config, migration, or offline tests. The root `default.yaml` is retained as supplied; `config/default.yaml` is the active app config.

## Remaining milestones

## Sprint 3.1 — Runtime hardening and migration recovery

- Migration 008 retains the original `provider_slot` separately from the resolved chain `slot`; existing migration events are queued for verification and unverified `migration_slot` values are cleared. A recovery worker resolves signatures through finalized Helius transactions and validates signature, mint participation, success, and slot before an atomic update. Failed or missing evidence produces a durable migration-specific analysis job.
- Migration-first candidates receive security and risk reports without being treated as creations. Previously verified creator history can be reused from Pump CreateEvent evidence. Missing creation evidence remains unknown and causes `QUARANTINE`.
- PumpPortal errors, recognized acknowledgements, unsupported frames, and malformed frames are dispatched separately. Bounded sanitized diagnostics persist and appear in read-only health; token detail shows migration recovery and analysis outcomes.
- The compatible `risk.emergency_pause` setting pauses new BUY exposure only. A valid SELL can reduce an existing position during the pause or after a drawdown and is still subject to atomic held-balance, quote, liquidity, fee, slippage, and ledger checks.
- Deterministic tests cover migration resolution, restart recovery, failed/mismatched/unrelated transactions, incomplete migration-first quarantine, provider frame classification and redaction, profitable/loss-making/partial SELLs, paused SELLs, drawdown, overselling, and unavailable exit quotes.
- Follow-up validation on 2026-11-01: all 77 tests, typecheck, lint, format check, docs check, build, and fresh migration 008 passed. The isolated database contains schema versions 1–8 and passes `PRAGMA integrity_check`. A bounded real worker session observed PumpPortal create and migration events; Helius resolved the migration signature to a successful transaction at slot `464032830`, and the matching mint and migration slot were persisted. The analysis decision was `QUARANTINE` because the deliberately small Helius budget was exhausted before all security evidence could be collected. This verifies migration recovery and fail-closed reporting for that event, not complete token analysis or trade coverage. A real migration payload fixture was not committed, and provider-reported migration wallet roles remain unverified.
- The same bounded run classified provider error and control frames separately and persisted sanitized diagnostics. A historical Pump create transaction summary exposed a BigInt JSON serialization failure; transaction-summary serialization now stores the event timestamp as a decimal string, with a regression test. No `.env` database was opened or modified.
- This work does not complete Milestone A. PumpPortal metered trade access and uninterrupted launch observation coverage remain unverified. PAPER mode remains unavailable and LIVE signing/submission remains absent.

1. Capture and validate PumpPortal migration events and verify event-version role semantics against finalized transactions; current migration payload behavior is an explicit limitation.
2. Capture a real trade payload after the operator provisions a PumpPortal linked wallet meeting the provider minimum. Then implement the single-socket subscription lifecycle, event budget accounting, reconnect coverage records, and normalized persistence before enabling behavior completeness.
3. Add a Helius-backed missed-launch reconciler only after validating program-history paging and historical Pump instruction/event variants; current stream gaps remain unrecovered.
4. Expand token security with supported token extension decoding and audited allowlists; currently unknown extensions fail closed and several known extensions are classified conservatively.
5. Expand quote validation across more live snapshots, migration races, fee configurations, and provider slot skew. Current Pump curve and PumpSwap vectors are verified from single snapshots and high-impact Pump curve results correctly fail current policy. No profitability metric is calculated from incomplete trading history.
6. Add authorized dashboard and configuration workflows after API contracts stabilize; the API remains read-only.
7. Keep the PAPER library isolated and inactive until Milestone A and operational mode-isolation gates pass; LIVE signing and submission remain unimplemented and isolated.
